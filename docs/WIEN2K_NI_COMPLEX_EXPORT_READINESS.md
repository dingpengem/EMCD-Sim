### Cross-file consistency

Both SOC streams were read as little-endian sequential Fortran records, with
4-byte record markers and complex128 coefficient records. Record lengths and
trailing markers were checked through EOF, including G lists, each band
energy/index and every complex coefficient record. The one-atom parameter
preamble contains two records; each k header has three coordinates, a name,
basis size, band count and trailing weight.

All four vector/energy views, both weight files and klist agree on **2,744
k-points and 60,858 band states**, 18-24 bands/k. Maximum cross-file energy
difference is **8.88e-16 Ry**; maximum k-coordinate difference is **4.29e-13**
in the stored reciprocal coordinate convention. The spin-component energy
files differ in their radial/basis preambles as expected but describe the same
SOC eigenstates. Summing them as independent spin transitions would double count.

Numerical EF is recovered, not inferred: **0.5443187936893177 Ry** in both
weight headers, consistent with scf2up/dn rounded EF=0.5443187937. The retained
band energies span -4.2565703177..1.8992915741 Ry. Although inop requests
-5..3 Ry, the SOC band set ends at about 1.9 Ry; an OPTIC rerun cannot generate
uncomputed higher bands. Any later requirement for a wider final-state window
would require additional upstream diagonalization, not a silent OPTIC setting.

Core wavefunctions and scfcup/dn independently provide:

| Edge / core | spin-up radial core energy (Ry) | spin-down radial core energy (Ry) |
|---|---:|---:|
| L3 / 2p3/2 (`2P`) | -60.534300889 | -60.511402243 |
| L2 / 2p1/2 (`2P*`, export label `2ps`) | -61.819104105 | -61.796955216 |

The old injoint uses the spin-up values. The raw SOC transition export combines
both spinor/radial channels. A future energy assignment must retain both sets

this audit does not substitute a guessed average, a single spin channel or

The relevant **installed** source confirms:

  COR_MAT/OUTMATABZ. Keep the ordinary XMCD two-column setup; change only OFF

  coherently combines the two spinor contributions before OUTMATABZ.
- With ON, outmatABZ writes unsquared complex Cartesian quantities to unit 4

  Re(px), Im(px), Re(py), Im(py), Re(pz), Im(pz). Printed precision is about

### Operator, axes and handedness limits

The inspected mmatcv convention is core-bra gradient, with source momentum
factor -i applied before output: native `<core|p_cartesian|SOC band>`-type
matrix elements. Struct gives identity local rotation and magnetization [001].
Cartesian x/y/z, radial spin components, coherent SOC phases and atom/site
identity must be retained. Native units follow the atomic-unit radial and
normalization implementation; they are **not angstrom dipoles**. Source
normalization includes `4*pi*RMT^2/sqrt(VOL)`. Unit/volume/site multiplicity
and the momentum-to-velocity interpretation must be validated, not discarded
as an arbitrary common amplitude factor.

Installed outmatABZ uses O_x+i O_y and O_x-i O_y for the two circular
intensities, with its specific y-component convention in mmatcv. The saved
symmat header calls the first column LEFT, whereas JOINT's final header calls
its first column RIGHT. No physical helicity or EMCD eta sign is inferred
merely from those names. A subsequent export must compare sums of the native
complex circular projections against each saved symmat column in its actual
order before attaching physical handedness. Do not conjugate or rescale
components to force agreement.

No conversion to length gauge was made. In particular, a local nonrelativistic
commutator conversion is not automatically valid for this relativistic/SOC
radial implementation. Core energy assignment and operator/normalization
checks must precede any length-gauge interpretation.

## 4. Future export contract (native momentum only)

This is a contract proposal, not an implemented exporter or populated dataset.
Use an immutable manifest plus one row per site/core j,m_j/k/SOC-band:

| Fields | Required meaning |
|---|---|
| site_id, species, fractional_position | Atom 1, Ni, (0,0,0), plus cell/rotation provenance |
| core_n, core_l, kappa, two_j, two_mj, edge | L3=(2,1,-2,3), L2=(2,1,+1,1); retain inferred m_j order with source/build hash |
| core_radial_energy_up_ry, core_radial_energy_dn_ry | Both actual spin-radial energies; do not conflate with a validated m_j excitation energy |
| core_energy_policy, resolved_core_energy_ry | Explicit validated policy and resolved value when available; unresolved must remain null |
| k_index, k_coordinates, coordinate_basis, k_weight | Exact klist/energy coordinates and BZ normalization, not rounded OPTIC log coordinates |
| soc_band_index, band_energy_ry, fermi_energy_ry | Verified common SOC eigenvalue and energy zero; one spinor band, not duplicate spin channels |
| occupation_factor, empty_final_factor, integration_scheme | Defined separately from k quadrature, including spin/statistical/core factors |
| px_re, px_im, py_re, py_im, pz_re, pz_im | The six native output values without phase replacement; record print precision |
| operator, native_units, amplitude_order | Cartesian native momentum; core bra / final ket; unit/normalization status explicit and pending until checked |
| magnetization, global_axes, local_rotation | [001], crystal/Cartesian axis basis and identity local rotation for this case |
| code_version, executable_sha256, source_hashes, build_id | Actual installed WIEN2k build identity, flags and export input/definition hashes |
| source_state_hashes, original_block, row_ordinal | Immutable linkage to both spinor files, core files, energies, klist and parent export location |

**Weights require care.** The recovered TETRA 101 files are not simple
occupation probabilities. Their weight/first-filled-band ratios range
**-0.4774945 to 1.2342743**; the first-band weights sum to
1.0000000000000289. Installed JOINT divides fci by the filled-band weight
and ARBDOSX uses (1-FC) in tetrahedron integration. Preserve those signed
quadrature data and tetrahedron topology separately. Do not clip them or
feed them directly into TransitionDataset's required nonnegative transition
weights. A future integration/occupation contract must explicitly reproduce
or deliberately replace the original quadrature with independently validated
positive-weight physics; native amplitude export alone does not solve this.

An alternative contract may store the complete Hermitian Cartesian products
Pxx,Pyy,Pzz,Re/Im(Pxy),Re/Im(Pxz),Re/Im(Pyz), together with the same indices,
energies, normalization and quadrature metadata. Core m_j may be summed only
with an explicit full-core product policy. This is sufficient for a dipole
tensor without individual amplitudes; the ordinary two circular symmat
projections are not sufficient. No artificial phase factorization into fake
dipole rows is acceptable. The recovered ON path offers amplitudes, so a new
product-export source modification is unnecessary for the first pilot.

## 6. Read-only reproduction and remaining limits

The small `scripts/wien2k_export_readiness.py` utility inventories/hash-checks
the two original trees, resolves the saved definition, validates SOC vector
record framing, matches bands/energies/k coordinates/weights, validates core
radial counts and compares source member hashes. It writes only JSON stdout;
licensed sources and amplitudes are not included in the output. Example
from Windows (no WIEN2k program is called):

```powershell
wsl.exe -d Ubuntu-20.04 --exec python3 `
  /mnt/c/Users/peng863/EMCD-Sim/scripts/wien2k_export_readiness.py `
  --archive /mnt/c/Users/peng863/Downloads/WIEN2k_18.2.tar
```

The parser intentionally targets this observed one-atom, gfortran complex
record format; it is not a general WIEN2k vector importer. WSL inspection used
Python 3.8; the two focused in-memory record/definition tests passed in the
existing Windows emcd-python environment (Python 3.11.17). No broad regression,
DFT, scattering, export or EMCD calculation was run.

Remaining risks are native amplitude print precision, exact operator/radial
normalization, physical helicity assignment, spin-dependent core-energy policy,
signed tetrahedron versus positive transition weights, finite basis/band/mesh
coverage, and absence of an executed ON-output test. Full physical convergence
and quantitative Ni MDFF accuracy are not established. **Stop at Phase 2A:**
readiness and the future contract are documented; no tensor or exporter has
been implemented and no electronic-state rerun has been performed.
